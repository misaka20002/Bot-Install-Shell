# 云崽开发环境清理

入口：`系统管理 → 4. 清理系统垃圾 → 2. 云崽开发环境清理`。

确认后清理 pnpm 无引用包、npm 缓存、当前用户的 npm `_npx` 与 pip/pnpm/node-gyp 缓存、APT 缓存与索引，并轮转 journal 后保留约 50M。工具未安装时跳过；旧版 APT 若不支持 `distclean`，索引清理会明确报错，不绕过 APT 锁直接删除。缓存重建需要重新下载。

云崽日志按 `$HOME/TRSS-Yunzai/logs` 与 `$HOME/Miao-Yunzai/logs` 定位（`GitBot.sh` 固定把 bot 克隆到 `$HOME/${BotName}`），两个目录都存在时都清，缺失的逐个提示后跳过。只处理文件名形如 `command.YYYY-MM-DD.log`（含 `.log.zst` / `.log.gz`）的文件：日期早于「今天 - 6」的删除，即保留今天与前 6 天。日期取自**文件名**而不是 mtime —— 迁移或 rsync 改过 mtime 也不会误判（「今天」取宿主机本地日期，与 log4js 生成文件名用的是同一时区）；取出的日期还会 `date` 回读校验，`2026-02-30` 这类不存在的日期按未识别处理。`command.log`、插件自己的日志、手工备份、同名目录与符号链接一律不动，`logs` 目录本身是符号链接时整体跳过。

`error.log` 只 `truncate -s 0` 原地清空，绝不 `rm` 后重建：log4js 的 `file` appender 由 bot 进程持有 append 流，文件被删后它会继续往已删除的 inode 写，重启前所有错误都会丢。truncate 保留 inode、属主与权限，运行中的 bot 立刻继续可写，所以清理**不需要停 bot**。`error.log` 不存在时只提示、不新建 —— root 建出来的 0644 会挡住非 root 运行的 bot。任一删除或清空失败都会让本函数返回非零，最终汇总为「部分清理失败」。

Hapi 按 `HAPI_HOME`（默认 `~/.hapi`）定位运行时。参考 Hapi 源码 `cli/src/projectPath.ts`、`configuration.ts`、`runtime/assets.ts`：编译版按包版本选择 runtime 子目录，并写入 `.runtime-version`。只将早于当前命令版本、标记吻合的普通目录列为候选，展示大小并单独确认。当前版本、新版本、软链接和未知目录保留。检测到 Hapi 进程，或版本与进程信息无法可靠读取时，跳过整个 Hapi 清理。建议在停止 Hapi 后执行；确认后会再次检查，但不能防止其他进程恰在删除瞬间启动。

临时目录只匹配 `/tmp` 第一层的 `html-tool-chromium`、`hapi-src`、`clash-review.*`、`sf-douyin-test-venv`、`at-graph-*`，且目录修改时间超过 7 天。展示大小后确认删除。目录修改时间不代表内部文件最近使用时间，确认前应自行确认相关任务已结束。

Docker 展示镜像列表，只删除输入的单个镜像，不加 force；容器引用的镜像交给 Docker 拒绝删除。回车跳过。

最终显示根分区可用空间变化，可能受到同期其他进程读写影响。部分失败返回非零；跳过项单独提示。这里的操作会在运行脚本的 Linux 主机上执行，开发验证不会清理本机数据。

定向验证：`node tests/SYS_Manage/cleanup.test.cjs`、`bash tests/SYS_Manage/cleanup-run.sh` 与 `bash tests/SYS_Manage/yunzai-logs.sh`。第一条以替身检查 Hapi 候选与保留规则；第二条检查失败返回及取消路径，不执行真实清理；第三条在隔离的 `HOME` 下用真实临时文件断言云崽日志规则（7 天边界、按文件名而非 mtime、非法日期不删、`error.log` 原地清空且 inode / 硬链接内容不变、缺失时不新建、白名单外文件与软链不动），并走一遍清理函数的 `y` 路径确认接线真的调到了本函数。
